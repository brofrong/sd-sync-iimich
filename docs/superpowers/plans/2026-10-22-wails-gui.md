# Новый интерфейс на Wails v3 — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** заменить меню `getlantern/systray` и AppleScript-диалоги окном на Wails v3 (тёмное окно, стеклянные карточки), которое объясняет, почему синхронизация не идёт; добавить автопродолжение, «Извлечь карту», историю, i18n на 8 языков и поставку в виде `.app`.

**Architecture:** Go-ядро (`scanner`, `uploader`, `immich`, `state`, `volume`, `update`) остаётся. `internal/app` начинает выдавать структурный статус «код + параметры + действия» вместо русских строк. Новый пакет `internal/gui` поднимает приложение Wails: сервис для фронтенда, события `status`/`state`, меню в трее, окно и Dock. Фронтенд на Svelte 5 + TS + Vite лежит в `frontend/` и встраивается в бинарник через `embed`. Оттуда же Go берёт JSON-каталоги переводов. Бандл `.app` собирает сам бинарник (команда `make-bundle`), поэтому сборка релиза, `install` и миграция с v0.3.0 используют один и тот же код.

**Tech Stack:** Go 1.26+, Wails `v3.0.0-beta.34` (+ CLI `wails3` той же версии), Svelte 5, TypeScript, Vite, `@wailsio/runtime`, SQLite (`modernc.org/sqlite`), `codesign`/`diskutil`/`launchctl`.

**Spec:** `docs/superpowers/specs/2026-10-22-wails-gui-design.md` (макет: `docs/superpowers/specs/assets/2026-10-22-gui-mockup-glass-cards.html`, вариант B).

## Global Constraints

- Wails ровно `github.com/wailsapp/wails/v3 v3.0.0-beta.34`; CLI ставить `go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-beta.34`.
- Языки: `en` (по умолчанию и fallback), `ru`, `de`, `es`, `fr`, `pt-BR`, `zh-Hans`, `ja`. Логи — только английский.
- Go не отдаёт в UI готовые фразы: только `code`, `params`, `actions`. Все пользовательские тексты (окно, трей, уведомления) — из `frontend/locales/*.json`.
- Поведение загрузки из v0.3.0 не меняется: HTTP/1.1, 4 соединения, повторы 5 с / 30 с / 2 мин, watchdog 2 мин, остановка при недоступном сервере.
- Окно тёмное и непрозрачное, без `Backdrop`. Стекло (blur + шум + фиолетовый оттенок) — только у карточек. Свечение — только у выбранного раздела, главной кнопки и полосы прогресса.
- Анимации из спецификации обязательны. При `prefers-reduced-motion` они отключаются, при скрытом окне ставятся на паузу (нагрузка в фоне — анти-цель).
- Прогресс в событии `status` — не чаще 4 раз в секунду; строка прогресса в трее — не чаще 1 раза в секунду.
- Автопродолжение: `GET /api/server/ping` с паузами 30 с, 1 мин, 2 мин, 5 мин (дальше каждые 5 мин).
- Bundle: `~/Applications/SD Sync Immich.app`, исполняемый файл `Contents/MacOS/sd-sync-immich`, `CFBundleIdentifier` и метка LaunchAgent — `com.sd-sync-immich`, `LSUIElement=true`. Подпись ad-hoc (`codesign --force --deep --sign -`).
- В каждом релизе остаются ассеты `sd-sync-immich` (universal) и `checksums.txt`: через них обновляется v0.3.0. Добавляется `SD-Sync-Immich.zip`.
- CLI `run`, `install`, `uninstall`, `scan-test` сохраняются.
- Перед каждым коммитом зелёные: `go vet ./...`, `go test -race ./...`; после Task 6 ещё `cd frontend && npm run check && npm run build`.

## Review Focus

1. Карту выдернули посреди синхронизации → статус `card_removed` (а не `failed` или `cancelled`), автопродолжение не запускается. Тесты: Task 2 (`ResultStatus` с `cardRemoved`), Task 5 (`shouldResume`).
2. Та же карта после форматирования (имя то же, UUID новый) → `other_card_mounted` с обоими именами и кнопкой выбора, а не «ожидание карты». Тест: Task 2.
3. API-ключ, вставленный с пробелом или переводом строки, и URL с хвостом `/` или `/api` → сохраняются нормализованными; URL без `http(s)://` отклоняется понятной ошибкой. Тест: Task 6 (`normalizeServer`).
4. В переводе пропущен ключ или сломан плейсхолдер (`{host}` → `{хост}`) → показывается английский текст, сырой `{host}` в UI не появляется. Тест: Task 1.
5. «Синхронизировать»/«Повторить» нажимают несколько раз подряд или во время ожидания автопродолжения → идёт ровно одна синхронизация, автопродолжение никогда не отменяет уже идущую. Тест: Task 5.
