# Галерея

Дата: 2026-10-27. Статус: одобрен.

## Зачем

Вставил карту — и хочется сразу посмотреть, что наснимал, и показать кому-то, не дожидаясь,
пока всё уйдёт в Immich (загрузка большой карты идёт десятки минут). Сейчас для этого нужно
открывать Finder или ждать Immich.

**Успех:** вставил карту, открыл вкладку «Галерея» — через пару секунд видны снимки по дням,
по клику фото раскрывается крупно, листается стрелками. Заодно видно, какие фото уже в Immich.

Автор снимает только JPEG (Sony, карта на ~2000 снимков).

## Цели

1. Новая вкладка **«Галерея»** в боковом меню, вторым пунктом (после «Статус»).
2. Снимки с вставленной карты, **сгруппированные по дням**, самые новые сверху.
3. **Просмотр крупно** по клику: фото на чёрном фоне поверх окна, листание стрелками на экране
   и клавишами ← →, Esc закрывает.
4. **Статус на каждой фотке** — кружок в углу.
5. Работает во время загрузки и не мешает ей заметно.

## Не цели

- Редактирование, удаление, выбор фото для загрузки, отметка «не загружать».
- RAW и видео: показываются только JPEG. Остальные файлы не показываются; под заголовком
  карты пишется, сколько таких файлов («и ещё 12 файлов не показаны: видео и RAW»).
- Просмотр того, что уже лежит в Immich, или карт, которые сейчас не вставлены.
- Масштабирование (зум) и слайд-шоу.

## Анти-цели (провал, даже если «работает»)

- Галерея заметно тормозит загрузку или само окно (2000+ фото не должны вешать интерфейс).
- Через адрес картинки можно прочитать любой файл на диске, а не только снимок с карты.
- Галерея что-то пишет на карту (кроме того, что делает загрузка).

## Что видит пользователь

Утверждённый набросок: `.superpowers/brainstorm/29454-1793083913/content/gallery.html`
(не в репозитории; описание ниже — достаточное).

**Вкладка «Галерея».**
- Какую карту показывать: **выбранную для синхронизации, если она вставлена** (решение
  автора дизайна). Если она не вставлена — пустое состояние «Вставьте карту, чтобы посмотреть
  снимки» (и, если вставлена другая, не выбранная карта, — «Вставлена „X“, но синхронизируется
  „Y“» с переходом в «Карты», как на экране статуса).
- Шапка: имя карты, «N фото · в Immich M», тонкая полоска прогресса (доля в Immich).
- Группы по дням: заголовок «Сегодня, 27 октября», «Суббота, 25 октября» и т.п. (дата на
  языке интерфейса) и число фото в группе. Внутри — сетка миниатюр 3:2, ширина колонки
  подстраивается под окно (примерно 5 в окне по умолчанию).
- Пока карта читается — скелетон/«Читаю карту…». Если файлов нет — «На карте нет фото».

**Статус на миниатюре** — кружок 16 px в правом нижнем углу:
- зелёный с галочкой — **в Immich**;
- синий со стрелкой — **загружается сейчас**; у такой миниатюры снизу ещё полоска;
- пустой (тёмный с белой обводкой) — **ждёт** (ещё не загружен);
- красный с «!» — **ошибка** в последней синхронизации этой карты; рамка миниатюры красная.

Подписи статусов есть в просмотре и во всплывающей подсказке (title) миниатюры; легенда
на вкладке не нужна.

**Просмотр крупно.** Клик по миниатюре открывает слой поверх всего окна (как панель журнала):
- фото целиком по центру на чёрном (object-fit: contain);
- сверху: имя файла, дата и время съёмки, размер файла, статус (кружок + слово), кнопка ✕;
- по бокам кнопки ‹ ›, клавиши ← →; листание идёт по всем фото карты подряд, через
  границы дней; на первом/последнем фото соответствующая кнопка неактивна;
- внизу лента соседних миниатюр с выделенной текущей, клик по ней переходит к фото;
  счётчик «17 из 48» (номер внутри дня и число фото в этом дне);
- кнопка «На весь экран» (и клавиша F) разворачивает окно приложения в полноэкранный режим
  системы; Esc сначала выходит из полноэкранного режима, второй Esc закрывает просмотр
  (решение автора дизайна: сам просмотр не уводит окно в полный экран без спроса, потому
  что на Mac это анимация и отдельный рабочий стол);
- статус в просмотре обновляется так же, как на миниатюрах.

Статусы и счётчики обновляются вживую по ходу загрузки (не чаще ~1 раза в секунду).

## Как устроено (решения)

**Список снимков (Go).** Новый метод сервиса для окна, например `Gallery() (GalleryView,
error)`: для выбранной вставленной карты обходит её тем же сканером, что и загрузка
(`scanner.ScanVolume` с текущим конфигом — те же папки и исключения), берёт файлы `.jpg/.jpeg`
и возвращает для каждого: идентификатор, имя файла, время съёмки, размер, статус. Остальные
файлы — только числом.

- **Время съёмки** — время изменения файла (камера пишет его в момент съёмки); EXIF не
  читается (решение автора дизайна: быстро и достаточно для группировки по дням). День
  определяется в часовом поясе компьютера.
- **Статус** берётся из того же, по чему решает загрузка:
  - «в Immich» — файл позади курсора синхронизации карты (`GetVolumeSync` +
    та же проверка, что `isAfterWatermark` в uploader — её нужно сделать доступной), или у
    него есть `uploaded_at` в таблице `files`;
  - «ошибка» — файл есть в `sync_run_failures` последней завершённой синхронизации этой
    карты и после неё не загружен;
  - «загружается» — файлы, которые загружаются прямо сейчас (идёт синхронизация этой
    карты). **Существующих данных для этого нет:** `Status.Progress.File` — последний
    *законченный* файл, а `uploaded_at` ставится ещё до того, как он туда попадает. Поэтому
    uploader должен вести множество файлов «в работе»: добавлять файл перед `syncOne`,
    убирать после (в `syncProgress`, рядом с `done`), и отдавать его в прогрессе — новое поле
    `Progress.InFlight []string` (относительные пути, не больше числа потоков, ≤16).
    Синими показываются все файлы из этого списка (решение автора дизайна). Проверка «в
    Immich» идёт раньше, так что законченный файл сразу становится зелёным;
  - иначе — «ждёт».
- Обновление статусов: окно перезапрашивает список (или только статусы) по событию состояния /
  прогресса, не чаще раза в секунду, и при вставке/извлечении карты. Повторный обход карты
  на каждый тик не нужен: файлы кэшируются до смены карты или конца синхронизации; статусы
  пересчитываются из базы (дёшево).

**Картинки в окно.** Окно получает картинки по HTTP с того же сервера ресурсов Wails:
к `application.AssetOptions` добавляется обработчик (middleware) путей вида
`/gallery/thumb/<id>` и `/gallery/photo/<id>`. `<id>` — идентификатор из последнего списка
`Gallery()`, **а не путь к файлу**: обработчик отдаёт только файлы из этого списка (анти-цель
про чтение произвольных файлов). Неизвестный id — 404.

- `/photo/<id>` — исходный JPEG как есть (`http.ServeContent`, с поддержкой Range и
  кэширования). Поворот по EXIF делает сам движок окна (`image-orientation: from-image` —
  по умолчанию в WebKit/WebView2/WebKitGTK; проверить).
- `/thumb/<id>` — миниатюра. Быстрый путь: встроенная в JPEG EXIF-миниатюра (IFD1, у камер
  обычно 160×120) — читается из первых ~64 КБ файла, без декодирования всего снимка. Если её
  нет — уменьшить снимок в Go до ~400 px по длинной стороне. Как именно (своя разборка APP1
  или небольшая библиотека) — на усмотрение исполнителя. Миниатюры кэшируются в памяти на
  время жизни карты (решение автора дизайна: на диск не пишем; 2000 × ~10 КБ = ~20 МБ — ок).
  Если EXIF-миниатюра выглядит слишком мыльно на Retina — допустимо фоном генерировать
  ~400 px и подменять.
- **Поворот миниатюр.** Встроенная миниатюра обычно не несёт своего тега Orientation (он
  только у основного снимка, в IFD0), так что `image-orientation` её не повернёт и
  вертикальные фото легли бы боком в сетке. Поэтому обработчик читает Orientation из IFD0 и
  отдаёт миниатюру уже повёрнутой (декодировать и повернуть 160×120 — дёшево; решение автора
  дизайна). Уменьшенная копия из запасного пути тоже поворачивается. Полный снимок
  `/photo/<id>` не трогается — его поворачивает движок окна (проверить на всех трёх).
- Чтение с карты идёт параллельно с загрузкой; ограничить одновременные чтения галереи
  (например, 2–4), чтобы не отнимать у загрузки чтение с карты.

**Окно (Svelte).**
- `sections/Gallery.svelte` — вкладка; добавить `"gallery"` в `sections` (stores.ts) вторым,
  иконку в `icons.ts`, ключи переводов на все 8 языков (`section.gallery` и тексты вкладки).
- Сетка большая: миниатюры грузятся лениво (`loading="lazy"`, `decoding="async"`), строки вне
  экрана не рисуются (`content-visibility: auto` для групп-дней или простая виртуализация).
  2000+ фото не должны подвешивать окно.
- `components/PhotoViewer.svelte` — слой просмотра, по образцу `LogsDialog.svelte` (Esc,
  фокус, `aria-modal`). Предзагружать соседние фото (±1), чтобы листание было мгновенным.
- Полноэкранный режим — через Wails (метод сервиса, который переключает
  `WebviewWindow.Fullscreen/UnFullscreen` и сообщает текущее состояние).
- Мок (`lib/mock.ts`) отдаёт список на ~2000 фото за несколько дней со всеми статусами
  и картинки (сгенерированные, без сети), чтобы вкладку можно было смотреть в браузере.

**Платформы.** Всё выше — общее для macOS, Windows и Linux; системного кода не нужно,
кроме полноэкранного режима (он в Wails).

## Тесты

- Go: файлы «в работе» в прогрессе uploader (появляются до загрузки, исчезают после);
  статусы файлов (позади курсора / uploaded_at / ошибка последней синхронизации / в работе /
  ждёт) на временной базе; группировка не в Go, но `Gallery()` отдаёт только JPEG и
  считает остальные; обработчик картинок отдаёт файл по известному id и 404 на неизвестный id
  и на попытки вида `../`; извлечение EXIF-миниатюры на тестовом JPEG (сгенерировать в тесте)
  и запасной путь без неё; поворот миниатюры по Orientation основного снимка.
- Фронтенд: `npm run check`; проверка в браузере на моке — группы, статусы, просмотр,
  стрелки, Esc, 2000 фото без подвисаний.
- Соблюдаются правила проекта: тесты не трогают настоящую карту, `/Volumes`, конфиг и базу
  пользователя (временные каталоги, `testenv.Home`).
