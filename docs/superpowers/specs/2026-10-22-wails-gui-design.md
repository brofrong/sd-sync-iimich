# Новый интерфейс на Wails v3

Дата: 2026-10-22. Статус: дизайн, ожидает одобрения.

## Зачем

Главная боль автора: синхронизация не запустилась или остановилась, и непонятно почему.
Сейчас, чтобы разобраться, приходится отдавать `app.log` нейросети. Текущий интерфейс —
вложенные подменю `getlantern/systray` и отдельный AppleScript-диалог на каждое поле —
причину не показывает и правится неудобно.

**Успех:** человек открывает окно и сразу видит, что происходит, почему синхронизация
не идёт и одной кнопкой может это исправить. Логи остаются только запасным вариантом.

Вторая цель: проект будут продвигать (r/immich, Хабр и т.п.), поэтому окно должно быть
красивым и хорошо смотреться на скриншотах и GIF, а интерфейс — многоязычным.

## Цели

1. Окно приложения на **Wails v3** с разделами: Статус, История, Карты, Сервер, Логи, Настройки.
2. Понятное объяснение причины для каждого состояния, когда синхронизация не идёт, плюс
   кнопка действия там, где оно есть.
3. Все настройки, которые сейчас есть в подменю трея, переезжают в окно.
4. Две новые функции (подтверждены автором):
   - **автопродолжение**: если синхронизация остановилась из-за недоступного Immich, а карта
     всё ещё подключена, приложение само продолжит, когда сервер снова ответит;
   - **«Извлечь карту»**: кнопка на экране «Готово» и в разделе Карты.
5. **i18n** с первого дня: en (по умолчанию), ru, de, es, fr, pt-BR, zh-Hans, ja.
6. Приложение поставляется как `.app`-бандл.

## Не цели (в эту версию не входит)

- Одновременная синхронизация нескольких карт. Остаётся одна выбранная карта; раздел Карты
  показывает подключённые карты и позволяет выбрать нужную.
- Замена ватермарка по mtime на учёт загруженного по каждому файлу. Это отдельная задача.
- Подпись и нотаризация Apple, Homebrew tap. Это отдельная задача.
- Хранение API-ключа в Keychain: ключ остаётся в `config.yaml` (0600).
- Альбомы на каждый импорт, Windows и Linux.
- Отдельный мастер первого запуска (см. «Первый запуск» ниже — достаточно подсказок на экране Статус).

## Анти-цели (провал, даже если «работает»)

- Красивое окно, которое так же не объясняет причину, как старое меню.
- Регрессия загрузки: скорость (HTTP/1.1, 4 соединения), повторы, остановка при недоступном
  сервере из v0.3.0 должны остаться как есть.
- Сломанное автообновление у тех, кто сейчас на v0.3.0 (голый бинарник + LaunchAgent).
- Заметная нагрузка в фоне: при закрытом окне анимации и WebView не должны тратить CPU.
- Окно «в стиле Electron» на сотни мегабайт: используется системный WebView, а не встроенный Chromium.

## Решения автора

**Окно.** Обычное окно с разделами в боковой панели слева (а не всплывающая панель из трея).

**Визуальный стиль** (макет: `assets/2026-10-22-gui-mockup-glass-cards.html`, вариант B):
- Окно тёмное и **непрозрачное**, рабочий стол сквозь него не просвечивает.
- **Стеклянные только карточки**: мутное матовое стекло с шумовой текстурой и лёгким
  фиолетовым оттенком, будто «слой стекла поверх» тёмного окна.
- Фиолетово-синий акцент **со свечением только на активных элементах**: выбранный раздел,
  главная кнопка, полоса прогресса.
- Карточка статуса меняет цвет по состоянию: идёт синхронизация — акцент, ошибка — красная,
  готово — зелёная.
- Автору важны «классные анимации». Как минимум те, что в макете:
  - подсветка раздела переезжает к выбранному пункту с пружинкой;
  - смена состояний карточки — плавный fade/slide;
  - по полосе прогресса бежит блик;
  - карточка ошибки коротко вздрагивает;
  - на «Готово» рисуется галочка.

**Языки.** i18n закладывается сразу. Язык берётся из системы, в Настройках его можно сменить
вручную. Логи остаются на английском.

## Решения, принятые мной (автор их не обсуждал отдельно — проверить при чтении)

- **Трей.** Клик по иконке показывает короткое меню: строка статуса, «Синхронизировать сейчас»
  или «Остановить», «Открыть окно…», «Выход». Окно из клика по иконке сразу не открывается.
- **Dock.** Иконка в Dock видна, только пока окно открыто. Закрыл окно — приложение
  снова живёт только в menu bar.
- **Фронтенд:** Svelte + TypeScript + Vite. Анимации на CSS и Svelte transitions,
  отдельную анимационную библиотеку брать, только если CSS не хватит.
- **Тексты:** один набор JSON-каталогов по языку, им пользуются и фронтенд, и Go (меню трея,
  уведомления macOS). Go не отдаёт в интерфейс готовые фразы — только **код причины +
  параметры** (например `server_unreachable`, `{host: "immich.brofrong.ru", detail: "no such host"}`),
  текст собирает выбранный язык. Переводы, кроме ru и en, делаю сам; позже попросить носителей
  проверить через issues.
- **Первый запуск.** Отдельного мастера нет. Пока приложение не настроено, карточка
  на экране Статус ведёт по шагам: «Укажите сервер» → «Вставьте карту и выберите её».

## Состояния и причины (ядро задачи)

Каждое состояние, которое видит пользователь, = код + параметры + (опционально) действие.
Минимальный набор, который должен быть различим:

| Код | Когда | Что показать / действие |
|---|---|---|
| `not_configured` | нет URL/ключа | «Укажите сервер Immich» → открыть Сервер |
| `no_card_selected` | карта не выбрана | «Выберите карту» → открыть Карты |
| `waiting_for_card` | выбранная карта не подключена | имя выбранной карты, «вставьте её» |
| `other_card_mounted` | подключена карта, но не выбранная (в т.ч. та же карта после форматирования — новый UUID) | «Подключена "X", а выбрана "Y"» → [Выбрать эту карту] |
| `scanning` | сканирование | — |
| `syncing` | загрузка | текущий файл, N из M, байты, МБ/с, ETA, [Остановить] |
| `nothing_new` | новых файлов нет | время последней синхронизации |
| `done` | успешно | сколько загружено, длительность, [Извлечь карту], [Открыть в Immich] |
| `done_with_errors` | завершено, но часть файлов не загрузилась | сколько и почему (сгруппировать по причине), [Подробнее] |
| `server_unreachable` | DNS/соединение/таймаут, повторы исчерпаны | хост и деталь, «продолжу, когда сеть вернётся», [Повторить сейчас] |
| `auth_failed` | 401/403 | «Ключ отклонён» → открыть Сервер |
| `server_error` | 5xx после повторов | код и сообщение сервера, [Повторить] |
| `card_removed` | карту вынули во время синхронизации | сколько успело загрузиться, прогресс сохранён |
| `cancelled` | пользователь остановил | — |
| `failed` | всё остальное | текст ошибки + [Открыть логи] |

Последнее состояние с причиной сохраняется между запусками, чтобы после перезапуска было видно,
чем закончилась прошлая попытка.

**Автопродолжение.** Срабатывает в `server_unreachable` и `server_error`, пока выбранная карта
подключена: приложение периодически пингует сервер и, как только он ответил, перезапускает
синхронизацию. Прогресс уже сохраняется (ватермарк), загруженное повторно не грузится.
Интервал и стратегию пинга выбирает реализующий. Повторная синхронизация не должна
отменять синхронизацию, которую запустил пользователь (сейчас `SyncNow` отменяет текущую).

## Разделы окна

- **Статус** — карточка состояния из таблицы выше, ниже строки: карта (имя, объём), сервер
  (в сети/не отвечает, задержка), последняя синхронизация.
- **История** — последние синхронизации: когда, карта, загружено/пропущено/ошибок, объём,
  длительность, итоговый код. Для этого нужна новая таблица в SQLite (например `sync_runs`).
- **Карты** — подключённые съёмные носители (имя, объём, UUID), отметка выбранной,
  [Выбрать], [Извлечь]. Показать выбранную карту, даже если она сейчас не подключена.
- **Сервер** — URL, API key (скрыт, с показом по кнопке), [Проверить подключение]: показывает
  версию сервера или понятную ошибку.
- **Логи** — хвост `app.log`, [Скопировать], [Показать в Finder]. Нужно, чтобы удобно отдать лог в issue.
- **Настройки** — язык, число параллельных загрузок, автопоиск путей и форматов камер,
  проверка обновлений (сейчас она в меню трея) и автозапуск.

## Ограничения и что затрагивается в существующем коде

- **Wails v3 — бета** (на 2026-10 последняя v3.0.0-beta.32, стабильного релиза нет).
  Зафиксировать конкретную версию в `go.mod`. На неё же опираются трей, окна, меню и
  полупрозрачность/бэкдроп.
- **Go-ядро не переписывается.** `scanner`, `uploader`, `immich`, `state`, `volume`, `update`
  остаются; меняются `tray`, `settings` (AppleScript-диалоги уходят), `notify`, `app`
  (структурные статусы с кодами вместо `Message string`), `cmd`.
- **CLI сохраняется:** `run`, `install`, `uninstall`, `scan-test` работают как раньше;
  `run` запускает GUI.
- **Упаковка и обновление.** Сейчас релиз — голый бинарник, `install` копирует его в
  `~/Applications/sd-sync-immich` и ставит LaunchAgent (`KeepAlive`), автообновление
  атомарно подменяет файл по `os.Executable()` и проверяет SHA-256 из `checksums.txt`.
  Новая версия должна:
  - поставляться как `.app` (Info.plist с `LSUIElement`, иконка, bundle id);
  - **мигрировать пользователей v0.3.0**: их старый апдейтер скачает ассет `sd-sync-immich`
    и подменит голый бинарник. Новый бинарник при запуске вне бандла должен сам установить
    `.app` (например в `~/Applications`), перенастроить LaunchAgent на него и перезапуститься;
  - сохранить проверку SHA-256 при обновлении.

  Формат ассетов релиза (zip бандла, сырой бинарник для обновления изнутри бандла и т.п.)
  выбирает реализующий, но ассет `sd-sync-immich` должен оставаться рабочим путём
  миграции для v0.3.0.
- **Уведомления.** Сейчас `osascript`, потому что без бандла `UNUserNotificationCenter`
  не работает. В бандле можно перейти на нативные — на усмотрение реализующего.
- **CI и релиз.** В `ci.yml` и `release.yml` появляется сборка фронтенда (Node) перед `go build`,
  потому что ассеты встраиваются в бинарник. `go vet ./...` и тесты должны проходить в CI.
- **Выход.** Сейчас LaunchAgent с `KeepAlive: true` перезапускает приложение даже после
  «Выхода». Если реализующий это тронет, «Выход» должен действительно завершать
  приложение до следующего входа в систему.

## Уточнения реализации (мои решения после вычитки)

- **Статус Go → окно.** Одна структура на всё приложение, примерно
  `{code, params, progress?, actions[], at}`: `params` — словарь для подстановки в текст,
  `actions` — коды доступных кнопок (`retry`, `select_card`, `open_server`, `eject`…).
  Go **пушит** её событием Wails при каждом изменении; при открытии окно один раз забирает
  текущее состояние вызовом сервиса. События прогресса — не чаще ~4 раз в секунду.
- **Последняя причина между перезапусками** берётся из последней записи истории
  (`sync_runs`), отдельного хранилища нет.
- **Таблица `sync_runs`** (минимум): `id, started_at, finished_at, volume_uuid, volume_name,
  result_code, result_params (JSON), uploaded, skipped, errors, bytes, error_summary (JSON:
  причина → количество)`.
- **Автопродолжение:** `GET /api/server/ping` каждые 30 с, после нескольких неудач интервал
  растёт до 5 мин. Ручное «Синхронизировать/Повторить сейчас» останавливает ожидание и
  запускает синхронизацию сразу. Автопродолжение запускает синхронизацию, только если никакая
  уже не идёт. Через перезапуск приложения ожидание не переживает: после старта работает
  обычный сценарий «карта подключена → синхронизация».
- **i18n:** единственный источник — JSON-каталоги в одном каталоге репозитория; Go встраивает
  их через `embed` (меню трея, уведомления), фронтенд импортирует их при сборке. Отсутствующий
  ключ или язык → английский. Тест проверяет, что во всех языках есть все ключи из `en`.
- **Выбранная карта** остаётся в `config.yaml` (`watch.volume_uuid`, `watch.volume_name`).
- **Dock:** переключение политики активации приложения (accessory ↔ regular) при открытии и
  закрытии окна, а не только `LSUIElement`.
- **Миграция с v0.3.0:** бинарник считает себя «вне бандла», если `os.Executable()` не лежит
  внутри `*.app/Contents/MacOS/`. Проверка на каждом старте: если вне бандла — установить или
  обновить `.app`, перенаправить LaunchAgent на бинарник внутри бандла, запустить бандл и выйти.
  Если бандл уже есть, приоритет у бандла.
- **Трей при закрытом окне** обновляется только при смене состояния; строка прогресса —
  не чаще раза в секунду.
- **Уведомления:** на усмотрение реализующего (оставить `osascript` допустимо).

## Оставлено реализующему

- Структура Go-пакетов и привязок Wails (сервисы, события для статуса и прогресса).
- Конкретная раскладка разделов внутри окна, размеры окна, иконки — в рамках стиля выше.
- Интервал пинга для автопродолжения, формат таблицы истории, сколько строк лога показывать.
- Формат релизных ассетов и способ миграции (в рамках ограничений выше).
- Тесты: Go-ядро — как сейчас (TDD); для фронтенда — разумный минимум (например, проверка
  каталогов i18n на полноту ключей).
