# Версии для Linux и Windows (бета)

Дата: 2026-10-24. Статус: дизайн, ожидает одобрения.

## Зачем

Приложение продвигается в сообществе Immich, а там много людей с Windows и Linux. Сейчас
им пользоваться нельзя: всё, что касается системы, написано только под macOS. Цель —
дать им то же самое приложение.

**Успех:** человек с Windows 10/11 или настольным Linux скачивает один файл, ставит,
вставляет карту — и фото уходят в Immich так же, как на Mac. Если что-то не так, он в
один клик открывает issue на GitHub.

У автора нет машин с Windows и Linux и запасной карты: настоящую работу с картами на
этих системах впервые проверят первые пользователи. Поэтому всё выходит как «бета».

## Цели

1. Сборки для Windows (x64) и Linux (x64) с теми же функциями, что на Mac: окно, значок
   в трее, выбор и отслеживание карты, синхронизация при вставке, история, автоизвлечение,
   запрет сна, уведомления, автоформатирование, автозапуск, автообновление, 8 языков.
2. Пометка «бета» в описании релиза, в README и плашкой рядом с номером версии в окне.
3. В окне рядом с версией — значок GitHub (ссылка на репозиторий) и значок жука (новый
   issue), на всех системах.
4. Более жёсткий предохранитель при включении автоформатирования — на всех системах,
   включая macOS.
5. Сборка и тесты всех трёх систем в GitHub Actions; один релиз со всеми файлами.

## Не цели

- Подпись кода на Windows (сертификат стоит денег) и нотаризация на Mac.
- Пакеты под конкретные дистрибутивы (`.deb`, `.rpm`, Flatpak, Snap), Windows на ARM,
  Linux на ARM — позже, если попросят.
- Магазины приложений (Microsoft Store и т.п.).

## Анти-цели (провал, даже если «работает»)

- Автоформатирование на Windows/Linux стирает не ту карту, не тот диск или карту, где не
  всё есть в Immich. Правила безопасности те же, что на Mac, без послаблений.
- Mac-версия становится хуже: всё, что работает сейчас, должно работать так же.
- Окно или трей ведут себя на Windows/Linux так, что человек не может закрыть приложение
  или найти его снова.
- Для обычной работы (синхронизация, извлечение) нужны права администратора/root.

## Решения автора

- Все функции на всех системах, включая автоформатирование.
- Всё на Windows и Linux помечается «бета».
- Включение автоформатирования: предупреждение об опасности, кнопку подтверждения нельзя
  нажать первые **10 секунд** (видно обратный отсчёт). На **всех** системах, включая macOS.
- Рядом с номером версии в окне — значок GitHub и значок жука (issues).
- Windows: установщик `.exe`; Linux: AppImage; Windows 10/11; ограничение GNOME (трей
  только с AppIndicator) — принимается и описывается.

## Решения, принятые мной (проверить при чтении)

1. **Значки в окне:** в подвале боковой панели, рядом с номером версии и плашкой «Beta»
   (на Mac плашки нет). GitHub → `https://github.com/brofrong/sd-sync-iimich`, жук →
   `…/issues/new` с заранее заполненными версией приложения, системой и её версией (без
   личных данных, без адреса сервера). Ссылки открываются в браузере по умолчанию.
2. **Предохранитель:** в строке подтверждения кнопка «Включить» неактивна 10 секунд и
   показывает «Включить (10)», «(9)»…; «Отмена» доступна сразу. Отсчёт начинается заново
   при каждом открытии подтверждения. Текст предупреждения на всех системах один:
   «Все файлы с карты будут удалены после проверки, что каждое фото и видео есть в
   Immich. Это нельзя отменить.»
3. **Где хранятся данные:** конфиг и база — в папке настроек пользователя системы
   (Linux: `~/.config/sd-sync-immich`, как сейчас; Windows: `%APPDATA%\sd-sync-immich`),
   логи — Linux `~/.local/state/sd-sync-immich`, Windows `%LOCALAPPDATA%\sd-sync-immich\logs`.
4. **Установка и обновление:**
   - Windows: установщик ставит приложение для текущего пользователя (без прав
     администратора) в `%LOCALAPPDATA%\Programs\SD Sync Immich`, создаёт ярлык в меню
     «Пуск»; автообновление скачивает новый установщик, проверяет контрольную сумму и
     запускает его в тихом режиме, затем приложение перезапускается.
   - Linux: AppImage; автообновление заменяет сам файл AppImage (путь из `$APPIMAGE`)
     после проверки контрольной суммы и перезапускает приложение. Если приложение
     запущено не из AppImage — обновление только сообщает о новой версии со ссылкой.
5. **Автозапуск:** Windows — запись в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`;
   Linux — `~/.config/autostart/sd-sync-immich.desktop`. Переключатель в настройках как на
   Mac.
6. **Карта на Windows:** съёмный том с буквой диска (`DRIVE_REMOVABLE`); ID карты —
   серийный номер тома. **На Linux:** съёмный том, смонтированный обычным образом для
   настольного Linux (`/media/<user>/…` или `/run/media/<user>/…`); ID — UUID файловой
   системы. Подключение и отключение отслеживаются так, чтобы синхронизация начиналась
   за те же несколько секунд, что на Mac.
7. **Извлечение:** Windows — безопасное извлечение устройства, как в трее Windows; Linux —
   размонтирование и отключение питания устройства через UDisks2 (то же, что делает
   кнопка «Извлечь» в файловом менеджере), без root.
8. **Форматирование:**
   - те же правила, что на Mac: проверка всей карты, отсчёт 30 секунд, сверка ID карты
     прямо перед стиранием, тот же формат (exFAT/FAT32) и то же имя, только раздел
     съёмного устройства, никогда системный или несъёмный диск;
   - Windows — через системные средства форматирования тома; Linux — через UDisks2.
   - Если на конкретной машине форматирование требует прав администратора или пароля
     (Windows UAC, polkit), приложение **не** запрашивает их, а показывает
     «Не удалось отформатировать: нужны права администратора» и больше не пытается для
     этой карты (как сейчас после сбоя).
9. **Запрет сна:** Windows — системный флаг «не засыпать» на время синхронизации;
   Linux — запрет сна через systemd-logind (как `systemd-inhibit`). Если недоступно —
   просто пишем в лог.
10. **Уведомления:** нативные уведомления Wails на Windows и Linux (кнопки — где система
    их поддерживает); если недоступны — без уведомлений, только лог (запасного
    `osascript` там нет).
11. **Язык системы:** Windows — язык интерфейса пользователя; Linux — `LANG`/`LC_*`.
12. **Окно и трей:** на Windows/Linux нет Dock: закрытие окна прячет его, приложение
    остаётся в трее; пункт «Выход» в меню трея. Клик по значку в трее открывает окно.
13. **Имена файлов релиза:** `SD-Sync-Immich-Setup-x64.exe`,
    `SD-Sync-Immich-x86_64.AppImage`; все — в `checksums.txt`. Существующие Mac-файлы
    не переименовываются (на них завязано обновление v0.3.0).
14. **Версия:** следующий релиз — v0.5.0.

## Уточнения после вычитки (мои решения)

1. **Нет трея (GNOME без AppIndicator).** При запуске на Linux приложение проверяет, есть
   ли в системе трей (служба StatusNotifierWatcher на шине сессии). Если трея нет,
   закрытие окна **сворачивает** его (оно остаётся в панели задач и доке GNOME), а не
   прячет; синхронизация продолжает работать. На всех системах в окне есть кнопка
   «Выход» (в подвале боковой панели, рядом с версией и значками), так что выйти можно
   и без трея. Без трея обратный отсчёт форматирования отменяется из окна.
2. **Обновление на Windows.** Приложение скачивает установщик, проверяет контрольную
   сумму, запускает его в тихом режиме отдельным процессом с флагом «перезапустить после
   установки» и **само завершается**. Установщик ждёт, пока процесс приложения
   закончится (и, если тот не закрылся за ~30 с, завершает его), копирует файлы и
   запускает новую версию. Это та же схема, что на Mac (`OpenWhenExited`). Если что-то
   пошло не так, старая версия остаётся рабочей.
3. **Кнопки в уведомлениях:** на Windows (toast) и Linux (libnotify в GNOME/KDE) кнопки
   есть; там, где система их не показывает, остаётся клик по уведомлению → окно.

## Ограничения

- Wails ровно `v3.0.0-beta.34`; сборка Linux — с WebKitGTK, как требует Wails; Windows —
  WebView2 (есть в Windows 10/11).
- Go не отдаёт тексты в UI: коды и параметры; все новые строки на 8 языках, тесты
  паритета ключей проходят.
- Системный код разделяется по файлам `_darwin.go` / `_windows.go` / `_linux.go` за общими
  интерфейсами; общий код (сканер, загрузчик, Immich, база, логика приложения, окно) не
  дублируется. `go vet` и `go test ./...` проходят на всех трёх системах в CI.
- Всё, что трогает диски, процессы и систему, — за швами; тесты никогда не трогают
  настоящие диски, реестр, автозапуск или уведомления.
- Безопасность разработки: на машине автора работает живая Mac-установка с настоящими
  данными — ничего из этого не запускать и не трогать (как в прошлых планах).

## Оставлено реализующему

- Конкретные системные API и библиотеки (Win32 через `golang.org/x/sys/windows`, D-Bus для
  UDisks2/logind/уведомлений) и устройство швов.
- Как отслеживать подключение томов на каждой системе (события или опрос), если задержка
  — секунды.
- Настройка сборки NSIS и AppImage через инструменты Wails, матрица CI.
- Вёрстка значков и плашки «Beta» в существующем стиле.
